The problem

Nobody could tell which button was right

One component, .Button, held seven properties: style, color, size, icon, fixed width, state and theme. Multiplied out, that was 2,304 variants, most unused and many near-identical. Behind it sat a library of 1,316 assets across 8 teams that nobody had ever measured.

  • IconsA variant, not a boolean, so one icon multiplied the whole matrix by 4.
  • Fixed widthA variant too, so turning it on doubled everything else in the matrix.
  • Disabled stateOne per color, so the same disabled look got defined again and again.

The design

The agent counted, the designer decided

One senior product designer built an agent on Claude and ran it through every Figma file: it listed each variant, found every instance in the product files and flagged what was unused or duplicated. From its list they kept 321, split into Button, Icon Button and Link, and had the agent write the usage guideline.

Split by purpose

Button, Icon Button and Link each got their own component, so the name says what it is for.

Booleans over variants

Left and right icons became toggles and the icon itself a swap, so they add nothing to the matrix.

One disabled state

Danger, Brand and Action reuse Primary's disabled variant instead of defining their own.

The full audit

Then I measured the whole library

I built a Claude Code agent and gave it a read-only Figma token, so it could open every file at Best Egg. It read every instance against the design system: what was used, what was not and where the system got in its own way. That list is what the remediation works from.

Connect Figma

I generated a Figma token and gave it to Claude Code, so it could reach every page and every instance in the file.

Audit everything

Claude Code audited every file against the design system, so what needed fixing came from the counts, not a hunch.

Split the fixes

Claude then built an interactive remediation guide, split between what it could do itself and what I directed the team to do.

My role

The full audit, the direction and the line

The full audit

I built the agent and ran the whole-library audit myself: generated the Figma token, wrote the crawler's rules, registered the teams, excluded the archives and the library's own file, took a name-match heuristic out of the adoption formula and reported Brand Studio separately, because marketing collateral does not instance a dropdown.

The direction

I directed the remediation. The plan divided at write access: specs and lists to a Claude agent, every edit to the library to a senior product designer, and the order set by who could act. The button portion was one senior product designer's from start to finish, agent and remediation.

The line

The analysis narrowed decisions and people made them. 10px appeared 1,834 times and 12px 1,796, and the data could not pick one. The 92 dormant illustrations got a conversation with Brand Studio, not a deletion.

What the index showed

The system works, the housekeeping is overdue

Adoption sat at 90.7% across 1.15 million instances, so nobody was rebuilding components. The findings were housekeeping.

  • A token system, almost unbound

    Five collections and 229 variables exist, but nothing in the library is wired to them. 844,333 values are still hand-set instead.

  • A third of the library dormant

    770 components have zero instances, and 59 standalones are the real deprecation candidates.

  • Half the library is illustrations

    266 of 491 standalone components are hand-drawn art that every designer scrolls past to reach the button components. 174 are in use, so they move, not go.

The remediation

Twenty-three fixes, split between the team and an agent

The agent wrote the remediation guide: a deep link into Figma for every fix, with the exact change to paste or click through. One senior product designer works the library edits from it while a Claude agent takes the specs and lists. The audit runs again on the first of every month, so drift, new components and finished fixes show up in the next report.

The library

A design system site that updates itself

With the set settled, the same agent built an internal design system site: every component rendered live, with its props, code and tokens on one page. It reads the component library in Figma and updates every week, so what the site shows is what the file holds.
