Agentic design system audit and remediation

An agent that audits Best Egg’s whole Figma design system, and the plan to fix what it found. It began with one overloaded button and grew into an audit of all 296 files.

Outcome

90.7%

Library adoption, measured for the first time across 296 files

Role
Director of Product Design
Team
2 senior product designers
Timeline
2 quarters
Coverage
296 of 296 files

The problem

One component, .Button, held seven properties: style, color, size, icon, fixed width, state and theme. Multiplied out, that was 2,304 variants, most unused and many near-identical. Behind it sat a library of 1,316 assets across 8 teams that nobody had ever measured.

  • IconsA variant, not a boolean, so one icon multiplied the whole matrix by 4.
  • Fixed widthA variant too, so turning it on doubled everything else in the matrix.
  • Disabled stateOne per color, so the same disabled look got defined again and again.

How I led it

The full audit

I built the agent and ran the whole-library audit myself: generated the Figma token, wrote the crawler’s rules, registered the teams, excluded the archives and the library’s own file, took a name-match heuristic out of the adoption formula and reported Brand Studio separately, because marketing collateral does not instance a dropdown.

The direction

I directed the remediation. The plan divided at write access: specs and lists to the agent, every edit to the library to a senior product designer, and the order set by who could act. The button portion was one senior product designer’s from start to finish, agent and remediation.

The line

The analysis narrowed decisions and people made them. The data could not pick between 10px, used 1,834 times, and 12px, used 1,796. The 92 dormant illustrations went to Brand Studio for a conversation instead of being deleted.

Key decisions

Three components instead of one

One senior product designer built an agent and ran it through every Figma file: it listed each variant, found every instance in the product files and flagged what was unused or duplicated. From its list they kept 321, split into Button, Icon Button and Link, and had the agent write the usage guideline.

Split by purpose

Button, Icon Button and Link each got their own component, so the name says what it is for.

Booleans over variants

Each side got an icon toggle, and the icon itself became a swap.

One disabled state

Danger, Brand and Action reuse Primary’s disabled variant instead of defining their own.

Cut

Icon as a variant

One icon property multiplied the whole .Button matrix by 4, and most of those variants were never used.

Kept

Icon as a boolean and a swap

Left and right icons became toggles and the icon itself a swap, so they add nothing to the matrix.

An audit of every file

I built an agent and gave it a read-only Figma token, so it could open every file at Best Egg. It read every instance against the design system: what was used, what was not and where the system got in its own way. That list is what the remediation works from.

Connect Figma

With the token, the agent could reach every page and every instance in each file.

Audit everything

The agent audited every file against the design system and counted what needed fixing.

Split the fixes

It then built an interactive remediation guide, split between what it could do itself and what I directed the team to do.

What the index showed

Adoption sat at 90.7% across 1.15 million instances, so nobody was rebuilding components. The findings were housekeeping.

  • A token system, almost unbound

    Five collections and 229 variables exist, but nothing in the library is wired to them. 844,333 values are still hand-set instead.

  • A third of the library dormant

    770 components have zero instances, and 59 standalones are the real deprecation candidates.

  • Half the library is illustrations

    266 of 491 standalone components are hand-drawn art that every designer scrolls past to reach the button components. 174 are in use, so they move to a library of their own.

A guide for every fix

The agent wrote the remediation guide: a deep link into Figma for every fix, with the exact change to paste or click through. One senior product designer worked the library edits from it while the agent took the specs and lists. The audit runs again on the first of every month, so drift, new components and finished fixes show up in the next report.

A site that rebuilds every week

With the set settled, the same agent built an internal design system site: every component rendered live, with its props, code and tokens on one page. It reads the component library in Figma and updates every week, so the site matches the file.

Screen recording of the internal design system site: the Button page, its props changed live, with anatomy, guidelines, code and tokens alongside.

Results

The button set came down to 321 variants across Button, Icon Button and Link. The full audit found the same pattern across 1,316 assets, and the remediation cut it back.
